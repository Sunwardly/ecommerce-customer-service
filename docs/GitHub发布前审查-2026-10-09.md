## 新环境验证中的具体问题

### 异步数据库依赖未声明完整

当前 `sqlalchemy>=2.0.49` 允许安装 SQLAlchemy 2.1.4；该环境未自动安装 greenlet，导入异步模块立即失败。pip check 不会识别这种可选功能依赖缺失。

本次仅在临时环境安装 greenlet，随后完整回归恢复为 30/30，应用初始化通过。修复应落到依赖配置与一致的锁文件，不应要求每个使用者临时补包。

### AI 状态表无法从模型生成 MySQL DDL

`model/state_record.py` 的 sender_id 使用没有长度的 String 推断，编译 CREATE TABLE 时返回 `VARCHAR requires a length on dialect mysql`。现有数据库已建表，故不影响当前查询；但新环境建表存在问题。建议显式使用 `String(64)`，添加迁移/初始化及类型回归测试。

业务后端也没有种子脚本，只有 ORM 模型无法复现 u1001 演示数据。README 的手工 AI 建表示例可作过渡，不替代完整迁移方案。

### npm 安全报告

受影响包：`vite`、`vue`、`@vue/server-renderer`、`postcss`、`nanoid`、`source-map-js`。这是受影响包计数，不是“页面已证实存在 6 个可利用漏洞”。SSR 漏洞需要 SSR 条件，本网站当前是客户端 Vue；Vite Windows 文件限制绕过针对网络暴露的开发服务器，不能直接套用为 preview 已确认漏洞。

已核对 [Vite Windows 文件限制绕过公告](https://github.com/advisories/GHSA-fx2h-pf6j-xcff)：当前锁定 6.4.2 在受影响范围，6.4.3 为该公告列出的 6.x 修复版本。另核对 [Vue server-renderer 公告](https://github.com/advisories/GHSA-g2v6-rqmx-r4w6)。最终升级目标需同时覆盖完整 npm audit 结果，不能只处理一个公告或直接使用强制升级。
