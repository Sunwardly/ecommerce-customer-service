# 访客会话独立

实施日期：2026-10-09。源码备份：backups/visitor-session-20261009-093844/。

## 使用行为

- 不同浏览器、不同设备或独立无痕环境首次访问时，各自获得独立聊天身份。
- 同一浏览器配置文件、同一网站地址的标签页共用 Cookie，因此共用当前聊天身份；不是每标签页独立。
- 刷新、重新打开页面继续恢复当前对话。Cookie 有效期为 30 天，清除 Cookie 或有效期届满后建立新的身份。
- “新对话”创建新的聊天身份和空状态，旧记录保留；不提供旧会话列表或恢复入口。
- 另一标签页在“新对话”后仍使用旧 sender_id 时，服务端返回 403，需刷新同步，避免消息被误写到新对话。
- 订单和商品仍展示 u1001 的共享演示数据，聊天身份不再作为业务用户 ID。
- 已有 u1001 历史保持原样，新访客不会自动继承它。
- 数字人仅在点击专用按钮后启用。后续已补充访问口令、演示业务权限和数字人单访客租约，详见《演示访问权限与数字人租约-实现说明.md》。

## 接口约定

| 接口 | 行为 |
| --- | --- |
| GET /api/visitor/session | 恢复有效 Cookie；不存在或无效时签发新的 Cookie，返回 sender_id 与 demo_user_id |
| POST /api/visitor/session | 要求有效 Cookie；为当前浏览器创建新对话，不删除旧记录 |
| POST /api/chat | 要求有效 Cookie；sender_id 可以省略，若传入必须匹配 Cookie |
| GET /api/chat/history | 要求有效 Cookie；只读当前身份，sender_id 参数可以省略，冒用其他身份返回 403 |
| WS /ws/avatar/chat | 握手验证 Cookie，连接固定绑定该聊天身份；消息不能改用其他 sender_id |

未经初始化的旧 API 调用方式会返回 401。脚本客户端现在需要先 POST /api/access/login，再 GET /api/visitor/session，并保留两个 Cookie。不能只指定 sender_id 来访问历史或发送消息。

Cookie 名为 ecs_visitor_session，使用 HttpOnly、SameSite=Lax、Path=/，HTTPS 请求下启用 Secure。当前演示域名仍为 HTTP，因此本次不能替代 HTTPS 的传输保护。

Cookie 包含随机对话标识、有效期及 HMAC-SHA256 签名；服务端只使用验证后的身份。签名密钥首次运行自动生成，保存在当前系统用户的应用数据目录 ecommerce-customer-service/visitor-session.key，不进入源码或 .env，不输出密钥内容。重启时复用该文件；迁移服务器需安全保留同一密钥，否则现有 Cookie 失效。当前实现面向单机部署；多实例需共享签名密钥。

数据库表结构、状态序列化与持久化格式未改变。

## 验证

前端 npm run build 通过。

```powershell
cd customer-service-backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

8 项权限回归通过，覆盖独立身份、刷新保持身份、新对话、无 Cookie、冒用身份、Cookie 篡改与过期、跨站轮换、WebSocket 身份校验。回归用例不调用 LLM 或数据库。

公网真实 API 验证通过：A/B 两个 Cookie 客户端各写入一轮测试对话，历史各有 2 条消息；A 的消息不出现在 B；越权读写均 403；A 新建对话后历史为空、B 不变、A 的旧记录仍保留；共享演示订单返回 5 条。另一 Python 进程能够验证服务端签发的 Cookie，确认本机签名密钥持久化可复用。

公网 WebSocket 实测通过：无 Cookie 的握手返回 403；持有合法 Cookie 的连接不能冒用另一个 sender_id；省略 sender_id 时按绑定身份处理。

浏览器实测通过：发送一条测试消息并收到回复，刷新后恢复该轮历史；点击“新对话”回到欢迎页，再次刷新不恢复旧消息，演示订单继续显示。验收截图：visitor-session-browser.png。

## 涉及代码

- api/visitor_session.py：签名、有效期、Cookie 验证与身份依赖。
- api/router/visitor_router.py：建立和轮换访客会话。
- api/router/chat_router.py、avatar_ws_router.py：HTTP 与 WS 权限边界。
- api/schemas.py、api/app.py：请求契约与路由装配。
- engine/dialogue_engine.py：回复携带本轮真实 sender_id / message_id。
- frontend/src/App.vue：会话初始化、业务身份分离、新对话、WS 重连、加载状态及只读演示用户。
